## Phase 3: Documentation Precision

**Duration:** ~1.5 hours

### 3a. Define "notebook required" threshold in POM

**Problem:** POM says journey notebooks are required "for non-trivial multi-stage work"
but never defines the threshold. An agent reading this cannot decide whether to create a
notebook.

**Concrete threshold to add** (add to the Compression Rules section of POM):

```
**Journey notebook required when ALL of:**
- Implementation spans ≥ 2 distinct phases or stages (e.g., parse → validate → store)
- AND at least one of:
  - ≥ 2 scripts or modules will be created or significantly modified
  - Work crosses a subsystem or repo boundary
  - The phase sequence has non-obvious dependencies between outputs

**Notebook optional (but recommended) when:**
- Work is a single linear script
- Implementation is a straightforward extension of existing pattern

**Notebook never required when:**
- Trivial exemption applies (≤ 20 lines, no new APIs)
- Single-file fix with clear acceptance criterion
```

**Location:** After the "Compression Rules" section in PLANNING_OPERATING_MODEL.md.

**Acceptance:** POM contains the words "≥ 2 distinct phases" in the notebook section.

### 3b. Mirror notebook threshold in Pattern 36

**Problem:** Pattern 36 (`36_executable-journey-notebooks.md`) says notebooks are needed

**Fix:** Add a "When is a notebook required?" section to Pattern 36 that quotes

### 3c. Define "governed repo" in README and GETTING_STARTED

**Problem:** The framework uses "governed repo" throughout (ROADMAP, install.sh, scripts)
but never defines what makes a repo "governed." Readers can't tell if they qualify.

**Canonical definition** (add to README under a "What is a Governed Repo?" subsection):
```
A **governed repo** is any git repository that:
1. Has a `meta-process.yaml` at its root (installed by `install.sh`)
2. Uses `[Plan #N]` or `[Trivial]` commit prefixes
3. Has `docs/plans/` with at least a `CLAUDE.md` plan index

That's it. The framework discovers governed repos by looking for `meta-process.yaml`.
You can verify governance with: `ls meta-process.yaml docs/plans/CLAUDE.md`
```

Add a cross-reference in GETTING_STARTED.md Step 3 (Verify).

**Acceptance:** README contains the phrase "governed repo" with an explicit definition.

### 3d. Fix Makefile infer-all fragility

**Problem:** `infer-all` target uses `ls -d $(SCAN_DIR)/*/` to iterate directories.
This includes every directory in `~/projects/` and silently skips non-governed repos
via an inner guard, but the `ls -d` approach breaks on:
- Repos named with spaces (ls splits on whitespace)
- Symlinks that point to directories

**Fix:** Replace the `ls -d` loop with a `find`-based approach:
```makefile
infer-all:  ## Infer deps across all governed repos in SCAN_DIR
	@find $(SCAN_DIR) -maxdepth 2 -name "meta-process.yaml" | while read config; do \
		repo=$$(dirname "$$config"); \
		echo "=== Inferring: $$repo ==="; \
		python scripts/infer_dependencies.py "$$repo" || true; \
	done
```

This uses the same discovery logic as `build_plan_registry.py` (look for meta-process.yaml).

**Acceptance:** `make infer-all` in a test with a space-named directory does not break.
The make target no longer contains `ls -d`.
